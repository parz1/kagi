# 已知问题

## AUTH-001：真实 agent 调用未显示系统验证框

**现状：2026-11-05 在同一台 Mac 上复现不出来，agent 发起的真实取值能弹框并通过；2026-10-27 那次的根因没有确定。** 验证流程没有改动：每次取值仍由 Secure Enclave 密钥操作触发一次系统验证，不缓存。

2026-10-27 真机验收中，同一台 Mac 的普通 Terminal 已通过建库、写入、更新、环境变量/标准输入注入和输出打码；从 Codex 发起真实取值请求时，用户未看到系统验证框，请求等待 120 秒后超时。采样显示进程停在 Secure Enclave 密钥操作触发的 LocalAuthentication 同步调用中。

### 排查结果

2026-11-05，macOS 27.2，Touch ID，一块显示器，Codex 0.166.0-alpha.6，调试版 kagi 和隔离的假库。

| 发起方 | 沙箱 | 测试框 | 临时密钥路径 | 真实取值 |
| --- | --- | --- | --- | --- |
| Terminal | 否 | 通过 | 通过 | 通过 |
| Claude Code | 否 | 通过 | 通过 | 通过 |
| Codex 线程（完全访问） | 否 | 通过 | 通过 | 通过 |
| seatbelt（Codex 的 `:workspace` 策略） | 是 | 被拦住 | 被拦住 | 被拦住，立刻退出 |

- **前三行除了发起方没有差别：** 引导命名空间都是 Aqua，安全会话相同，都能使用图形界面。
- **沙箱不会让进程卡住。** seatbelt 拒绝了 `com.apple.CoreAuthentication.agent` 和 `com.apple.ctkd.token-client` 的 mach-lookup，密钥操作 0.02 秒内以 `NSCocoaErrorDomain 4099` 失败。当时进程既然停在 LocalAuthentication 里，就不是被这个策略拦住的。
- **当时的采样不能证明框没有弹出。** 框正常显示、等人点击时，采样到的就是同一个栈：`TKClientTokenObject exchangeKey` → `LAContext evaluateAccessControl` → `LAClient _performSynchronous` → 信号量等待。
- **已排除：** launchd Background 命名空间（照常弹框）；前面有另一个框没处理（第二个框照常出现，叠在第一个上）；发起方 app 在后台（用 Terminal 测试，照常弹框）。
- **还能解释当时现象、但无法验证的可能：** 框出现了但没被注意到（这次排查就发生过一次：窗口 0.2 秒就出现，30 秒内没人注意到）；框出现在另一块显示器上；当时的系统或 agent 版本行为不同。

因为真实取值没有失败，没有改用「先 `evaluateAccessControl`，再把 context 交给密钥操作」的方案：它解决不了复现不出来的问题，却要改动每次取值的验证路径。

### 现在的行为

| 情况 | 退出码 | 表现 |
| --- | --- | --- |
| 在沙箱里 | 75 | 立刻退出，说明被沙箱拦住，并附系统的原始错误 |
| 屏幕锁着 | 75 | 立刻退出，说明屏幕锁着 |
| 框已弹出但没人处理 | 75 | 等到超时（默认 90 秒，`KAGI_AUTH_TIMEOUT` 可设 10–600）后取消；取消后系统调用仍不返回时直接退出 |
| 点取消 | 77 | 命令不运行 |

走到验证这一步才失败的会写进使用记录，`kagi log` 里分别显示「超时」「锁屏」「被沙箱拦住」；读名字时就失败的（在沙箱里、锁屏约 10 秒后）不写记录。GUI 不设超时，仍一直等待；屏幕锁着时同样立刻失败。

**在 agent 的沙箱里使用：** 需要在 agent 的设置里允许 kagi 在沙箱外运行，怎么配置看 agent 自己的文档，代价见[威胁模型](威胁模型.md)。kagi 不写死任何 agent 的配置。

### 再次遇到时

在同一台 Mac 上分别运行，并对比两份输出：

```bash
kagi doctor --prompt --json > terminal.json      # 自己的 Terminal
kagi doctor --prompt --json > agent.json         # 让 agent 运行同一条命令
```

`--prompt` 会弹两次框：`prompt` 只验证设备主人，`keyPrompt` 用临时 Secure Enclave 密钥走真实取值的路径。都不碰库，不读任何值。

- `sandboxed` 是 `true`：问题在 agent 的沙箱，在 agent 的设置里允许 kagi 在沙箱外运行。
- `screenLocked` 是 `true`：解锁后再试。
- 结果是 `timedOut`：先确认屏幕上有没有框。框显示时进程也在等待，采样不能区分这两种情况；系统验证框属于 `coreautha` 进程，可以看它有没有窗口。
- `prompt` 通过而 `keyPrompt` 不通过，或两者都通过而真实取值不弹：问题在 Secure Enclave 密钥操作本身，这是 2026-11-05 没有见到的情况，请保留这份输出。
