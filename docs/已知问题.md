# 已知问题

## AUTH-001：真实 agent 调用未显示系统验证框

2026-10-27 真机验收中，同一台 Mac 的普通 Terminal 已通过建库、写入、更新、环境变量/标准输入注入和输出打码；从 Codex 发起真实取值请求时，用户未看到系统验证框，请求等待 120 秒后超时。采样显示进程停在 Secure Enclave 密钥操作触发的 LocalAuthentication 同步调用中。

**根因仍未确定，弹窗本身没有修复。** 目前做了两件事，用来缩小范围并避免卡死：

- **不再无限等待。** CLI 等系统验证最多 90 秒（`KAGI_AUTH_TIMEOUT` 可设为 10–600），超时后取消这次验证并返回 75，说明里附带沙箱、图形会话等线索；取消后系统调用仍不返回时直接退出。GUI 行为不变，仍一直等待。
- **`kagi doctor` 对比启动上下文。** 输出发起方进程链、是否在沙箱里（含 `CODEX_SANDBOX` 等环境变量）、安全会话能否使用图形界面、Secure Enclave 与系统验证是否可用。`--prompt` 另外弹一次只验证设备主人的测试框，不读取任何密钥；`--json` 便于对比。

### 排查步骤

在同一台 Mac 上分别运行，并对比两份输出：

```bash
kagi doctor --prompt --json > terminal.json      # 自己的 Terminal
kagi doctor --prompt --json > agent.json         # 让 agent 运行同一条命令
```

- agent 一侧显示在沙箱里、或测试框超时，而终端一侧正常弹出：问题在 agent 的执行环境（例如 Codex 的 seatbelt 沙箱拦住了系统验证），需要在 agent 设置里允许 kagi 在沙箱外运行。
- 两侧测试框都能弹出，而真实取值仍不弹：问题在 Secure Enclave 密钥操作本身，需要继续排查。

### 尚未验收

超时与诊断目前只在 fake 和单元测试中覆盖。真机上的弹窗、取消、锁屏和超时，真实取消、锁屏、跨物理 Mac 恢复及发布版真实库操作都尚未验收完成；fake 验证覆盖了批准、拒绝与锁屏的业务流程，但不代表真实 agent 弹窗可用。
