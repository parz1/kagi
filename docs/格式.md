# kagi 库格式（第 1 版）

这份文档写给要独立实现 kagi 格式的人，包括 kagi 坏了之后的你自己。照着它，不看 kagi 的源码也能解开库。`recover/recover.swift` 就是只照着这份文档写的。

## 用到的算法

kagi 不自己设计算法，只组合下面这些标准件，全部由 CryptoKit 提供：

| 用途 | 算法 |
|---|---|
| 加密每条值、元数据、恢复包装 | AES-256-GCM，12 字节 nonce，16 字节 tag |
| 把库内密钥包给设备 | HPKE（RFC 9180）base 模式，套件 DHKEM(P-256, HKDF-SHA256) + HKDF-SHA256 + AES-256-GCM |
| 从恢复密钥派生加密密钥 | HKDF-SHA256 |
| 密钥校验值 | HMAC-SHA256 |
| 恢复密钥的校验位 | SHA-256 |

约定：
- 文中的「Base64」都是标准 Base64，带 `=` 填充。
- 「绑定串」是 UTF-8 字符串，用作 AES-GCM 的附加数据（AAD），也用作 HPKE 的 info 和 AAD。

AES-GCM 的结果统一存成 `Base64(nonce ‖ 密文 ‖ tag)`，也就是 CryptoKit 的 `AES.GCM.SealedBox.combined`。

## 两把库内密钥

每个库有两把随机生成的 256 位对称密钥：

- **库密钥**（secret）：加密每一条值。用它的设备密钥要求按指纹。
- **索引密钥**（index）：加密名字和元数据。用它的设备密钥不要求按指纹，所以 `kagi ls` 不弹框。

## 文件夹结构

```
<库>/
  vault.json
  keys/
    <设备 ID>.json
    recovery.json
  entries/
    <条目 ID>/
      0001.kagi
      0002.kagi
  index/
    <条目 ID>.kagi
```

- 库 ID：16 字节随机数，用小写 Crockford Base32 写出（26 个字符）。界面上只显示前 4 个字符，比如 `k-8mxh`。
- 条目 ID：10 字节随机数，小写 Crockford Base32（16 个字符）。
- 设备 ID：`mac-` 加上 5 字节随机数的小写 Crockford Base32。
- 版本号从 1 开始，文件名补零到 4 位：`0001.kagi`。每改一次就写一个新文件，旧文件不删。
- 所有 `.json` 和 `.kagi` 文件的内容都是 JSON，时间写成 UTC 的 ISO 8601（比如 `2026-10-25T12:54:49Z`）。

## vault.json

```json
{
  "format": "kagi-vault/1",
  "vault": "<库 ID>",
  "created": "<时间>",
  "keyCheck": "Base64(HMAC-SHA256(库密钥, \"kagi-key-check/1|<库 ID>|secret\"))",
  "indexKeyCheck": "Base64(HMAC-SHA256(索引密钥, \"kagi-key-check/1|<库 ID>|index\"))"
}
```

每台设备加入库时，都会把这两个校验值记在本机，然后每次打开库都拿 vault.json 来比对。网盘上有人换了钥匙或改了校验值，这一步就能发现。

## keys/<设备 ID>.json

```json
{
  "format": "kagi-device/1",
  "vault": "<库 ID>",
  "device": "<设备 ID>",
  "name": "<电脑名>",
  "created": "<时间>",
  "secretPublicKey": "Base64(设备密钥 A 的公钥，X9.63 非压缩格式)",
  "indexPublicKey": "Base64(设备密钥 B 的公钥)",
  "secretWrap": { "enc": "Base64(HPKE 封装的密钥)", "ciphertext": "Base64(HPKE 密文)" },
  "indexWrap": { "enc": "…", "ciphertext": "…" }
}
```

- 设备密钥 A、B 都是这台 Mac 的 Secure Enclave 里的 P-256 密钥，只能在这台设备上用。
  - A 的访问控制是「使用时要按指纹或输登录密码」。
  - B 不要求验证，但屏幕解锁时才能用。
- `secretWrap`：用 A 的公钥做 HPKE，封装的明文是库密钥的 32 个字节。info 和 AAD 都是 `kagi-device/1|<库 ID>|<设备 ID>|secret`。
- `indexWrap`：用 B 的公钥封装索引密钥。info 和 AAD 是 `kagi-device/1|<库 ID>|<设备 ID>|index`。

## keys/recovery.json

```json
{
  "format": "kagi-recovery/1",
  "vault": "<库 ID>",
  "secretWrap": "Base64(AES-GCM(加密密钥, 库密钥, AAD = \"kagi-recovery/1|<库 ID>|secret\"))",
  "indexWrap": "Base64(AES-GCM(加密密钥, 索引密钥, AAD = \"kagi-recovery/1|<库 ID>|index\"))"
}
```

### 恢复密钥

- 先生成 18 字节随机数 `s`。
- 校验位是 `SHA-256("kagi-recovery-checksum/1" ‖ s)` 的前 2 个字节。
- 把 `s ‖ 校验位` 一共 20 字节写成 Crockford Base32，正好 32 个字符，分成 8 组、每组 4 个，用 `-` 连接。
- 字母表是 `0123456789ABCDEFGHJKMNPQRSTVWXYZ`。解码时忽略大小写、横线和空格，把 O 当 0，I 和 L 当 1。

加密密钥 = HKDF-SHA256：
- 输入密钥材料是 `s`
- 盐是 `"kagi-recovery/1|<库 ID>"`
- info 是 `"kagi recovery key-encryption key"`
- 输出 32 字节

## entries/<条目 ID>/<版本>.kagi

```json
{
  "format": "kagi-entry/1",
  "vault": "<库 ID>",
  "entry": "<条目 ID>",
  "version": 2,
  "created": "<时间>",
  "box": "Base64(AES-GCM(库密钥, 明文, AAD))"
}
```

- AAD 是 `kagi-entry/1|<库 ID>|<条目 ID>|<版本>|<created>`。文件被挪到别的条目或版本下面，或者时间被改过，都会解密失败。
- 明文是 JSON：`{"ref": "<引用>", "value": "Base64(值的原始字节)"}`。解出来以后，还要核对 `ref` 和索引里的名字是否一致。

## index/<条目 ID>.kagi

```json
{
  "format": "kagi-index/1",
  "vault": "<库 ID>",
  "entry": "<条目 ID>",
  "box": "Base64(AES-GCM(索引密钥, 明文, AAD = \"kagi-index/1|<库 ID>|<条目 ID>\"))"
}
```

明文是 JSON：

```json
{
  "ref": "resend/api-key",
  "issuer": "Resend",
  "usedIn": "Kotolog 生产：Railway、Vercel",
  "created": "<时间>",
  "updated": "<时间>",
  "latestVersion": 2
}
```

`issuer` 和 `usedIn` 可以没有。读值时，以 `entries/<条目 ID>/` 里版本号最大的文件为准，`latestVersion` 只用来显示。

## 引用

引用由一段或多段组成，段与段之间用 `/` 分开，比如 `resend/api-key`。

每一段的规则：
- 只能用小写字母、数字和 `.` `_` `-`；
- 必须以小写字母或数字开头；
- 不超过 64 个字符。

整个引用不超过 200 个字符。

## 这台 Mac 自己的文件（不进网盘）

放在 `~/Library/Application Support/kagi/` 下面，目录权限 0700，文件权限 0600：

- `device.json`：库的位置、库 ID、设备 ID、记下的两个校验值，以及两把 Secure Enclave 密钥的 blob。这些 blob 只有在这台 Mac 的 Secure Enclave 里才用得了。
- `log.jsonl`：使用记录，一行一条 JSON，不含任何值。

## 不经过 kagi 怎么解开库

1. 读 `vault.json` 拿到库 ID；读 `keys/recovery.json`。
2. 按上面的规则解码恢复密钥，核对校验位，派生加密密钥。
3. 用加密密钥解开 `secretWrap`，得到库密钥。
4. 对每个 `entries/<条目 ID>/`，取版本号最大的文件，用库密钥解开，得到 `ref` 和值。

`swift recover/recover.swift --vault <库> --out <输出文件夹>` 做的就是这几步。
