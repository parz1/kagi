# kagi 的威胁模型

kagi 保存 API key、token、私钥文件和账号密码，并提供 TOTP 与 fake Passkey 核心。真实网站 Passkey 登录仍需浏览器或系统提供者接入。

## 要防的

### 1. Mac 丢了或被偷
- 库文件拷离这台 Mac 就解不开：设备密钥在 Secure Enclave 里，拷不走。
- 允许退回登录密码时，强度等于 FileVault 加登录密码。

### 2. 网盘或备份泄露
- 网盘上只有密文，元数据也是加密的，看不出你用了哪些服务。
- 能看到的只有：文件个数、大小、修改时间。
- 网盘服务商也改不了内容：每段密文都绑定了库、条目和版本，改了就解不开。

### 3. 同一用户下的恶意程序
- 每次取值都会弹出系统的指纹框，写明哪几条 key、交给哪条命令、由谁发起。
- 弹窗文字可以被伪造，但恶意程序做不到不弹框。
- 写入也要按指纹：没有库密钥就写不出能解开的条目，也就伪造不了条目。

### 4. AI agent：能用，不能看
- kagi 不提供把值打印出来的命令，只把值交给它启动的子进程。
- 子进程打出来的值会被换成 `‹kagi:引用›`。打码只防无意泄露，挡不住先编码再打印。
- 真正把关的是你：读完弹窗里的命令再按。`run` 不再截断命令，超出程序展示限制时拒绝运行。
- 授权说明包含解析后的可执行文件路径、工作目录和注入对应关系，但不绑定脚本/可执行文件内容。程序限制不等于系统弹窗的显示保证，需在真实设备上验收。
- 继承环境里能让子进程额外加载代码的变量（`NODE_OPTIONS`、`PYTHONPATH`、`BASH_ENV`、`ZDOTDIR`、`RUBYOPT`、`JAVA_TOOL_OPTIONS`、`GIT_SSH_COMMAND`、`DYLD_*`、`npm_config_*` 等，完整名单见 `Sources/KagiCore/EnvironmentPolicy.swift`）默认不交给子进程，否则弹窗里看似无害的 `node send.js` 也能先加载别的脚本。确需保留时用 `--pass-env`，变量名和值写进授权说明。名单是保守的缩小，不是沙箱：`PATH`、`HOME`、各工具的配置文件和其余继承变量仍会影响子进程。
- `kagi init` 和 `kagi recover` 会显示或要求输入恢复密钥，所以只能在你自己的终端里运行。agent 发起时会直接拒绝。

### 5. 剪贴板、终端历史、录屏
- 值不经过 kagi 的命令参数：`set` 用隐藏输入或标准输入。
- 值直接写在命令行里时，kagi 会提醒。
- 复制到剪贴板时（CLI 与 GUI）标记为隐藏、临时、只在本机，30 秒后清除。

### 6. 手滑
- 覆盖时旧值保留为上一版。
- 另有一条不经过 kagi 的恢复路径：`recover/recover.swift` 加上 `docs/格式.md`。

## 不防的

- **能改程序和文件、或拿到 root 的长期潜伏恶意软件。** 包括被诱导去改 kagi 的 agent。缓解：把 kagi 装在 root 所有的目录，比如 `/usr/local/bin`。
- **你亲手批准的恶意命令。**
- **注入之后、子进程运行期间的环境变量和参数。** 同一用户的程序能读到它们。
- **国家级攻击和胁迫。**
- **内存残留。**

## 已知的限制

- **网盘能删文件，也能换回旧版本。**
  - 内容伪造不了，但你可能拿到旧值，或者丢数据。
  - 第一版不检测回滚。网盘自带的版本历史和本机备份可以兜底。
- **「由谁发起」是按进程名猜的。**
  - 恶意程序可以把自己命名成 `claude`。它只是给你的提示，不是安全边界。
- **多设备写入与同步冲突。**
  - 本机写锁和排他发布避免同机写入互相覆盖；锁内重新核对授权前读取的条目快照。
  - 重复引用、异常版本文件、缺失/过期索引会报错；可用 `kagi repair-index` 在全库条目验证通过后重建缺失或过期索引。修复写入中断时可重跑，不提供全库事务。
  - 直接同步库目录时，本机锁不提供跨 Mac 互斥，仍须串行写入；静默同版本覆盖也可能无法检出。独立 `sync` 使用不可变快照和远端条件更新，按祖先合并并显式处理冲突。目录适配器仅对共享同一文件锁的访问者有效，不是跨网盘镜像的锁。
- **使用记录只能给认得的值打码。**
  - 记录里会存 agent 交给 shell 的整条命令；`set` 在批准、拒绝和解锁失败时都给本次输入值打码，包括短值。`run` 的输出仍跳过不足 6 字节的值，避免误伤正常输出。
  - 如果命令行里直接写了别的密钥明文，kagi 认不出来，这个值也已经留在了 agent 的记录和 shell 历史里。
- **钥匙被调包。**
  - 网盘上的人可以用设备公钥包一把自己的库密钥，再改掉 vault.json。
  - 这台 Mac 加入库时记下了校验值，打开库时会发现对不上，然后拒绝继续。
  - 新设备第一次加入时，只能相信恢复密钥解出来的钥匙。
- **设备丢了以后。**
  - 移除设备、更换库密钥要到第二版才有。
  - 在那之前，丢了设备就要轮换库里重要的 key。

## 管理扩展的边界

Space、标签、显示名称、备注和归档状态由索引密钥加密。组织结构与真实值分开；列表和 JSON 查询不会解密值，所有管理写入在应用流程中仍要求本次授权。Space 不是独立的加密/共享权限边界。

归档只是阻止正常 CLI 的默认发现和使用，不会撤销已经交给程序的值，也不会删除密文。索引丢失时无法从值恢复原有管理字段，修复结果会先归档，再由用户核对恢复。独立恢复脚本会导出所有条目的最新值，包含归档项。

## TOTP 与 Passkey 核心

验证器种子与私钥只进入加密值区，kind 同时保存在受认证的值和索引中。普通取值必须为 secret；TOTP 只能生成或注入临时验证码，Passkey 核心只输出注册公钥数据和签名响应。归档与快照检查继续适用于验证器凭据。独立人工恢复路径仍可导出原始种子和私钥，这不是针对持有恢复密钥的人的防护。

Passkey CLI 是 fake 核心联调，发布版禁止使用。请求内提供的 origin 不是可信浏览器来源证明，UP/UV 仅在测试中模拟；必须在接入真实平台时由可信适配器校验来源、完成每次用户验证，并正确管理备份状态。当前只支持完全匹配 RP ID 的 origin；没有跨源 iframe、父域推导、扩展、企业证明、计数器克隆检测或系统自动填充。真实 RP 仍需自行校验 challenge、允许的 origin、凭据账号、公钥签名并消费 challenge，防止重放。

fake 测试不绕过真实 Secure Enclave，也不证明 AUTH-001 已解决。验证器测试只使用公开 RFC 向量、临时软件密钥和本地验证器。

## 独立同步的信任边界

同步服务不需要理解明文，也不要求 Kagi 账号。对象用库密钥 AES-GCM 加密，认证绑定公开库头与恢复封装；对象 ID 是完整传输字节的 SHA-256。公开头与已有 `vault.json`/`keys/recovery.json` 等价，不包含凭据值、引用、标签或设备私钥 blob。服务仍可看到对象大小、版本图的 HEAD 变化、访问时机，并能删除或阻断数据。

有本地同步基线时，远端必须保留该祖先；历史回退或孤立分叉会拒绝。首次加入或本地基线丢失后，无法区分旧的真实快照与最新快照。基线与恢复日志本身加密认证，但不能抵抗具有本地文件回滚能力的攻击者。

合并以 key 整体与单个 Space 为单位；不同字段的并行修改也可能需要人工选择。拒绝用设备时钟决定密钥胜负。选择一侧会改变当前可用副本，另一侧仍在加密快照历史中；归档不等于撤销，历史保留也不等于安全删除。尚无跨设备密钥撤销与库密钥轮换。

安装前验证全部历史值及索引；CAS 失败不安装，安装中断后普通操作受恢复日志阻止，重新同步完成安装。已有进程的元数据查询可能短暂失败，敏感值读取与写入由本机锁协调。恢复日志不能使网盘镜像获得原子事务能力，工作副本应保存在本地，勿同时用外部同步工具修改它。
