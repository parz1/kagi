# 开发与测试

只依赖系统框架（CryptoKit、Security、LocalAuthentication、CoreGraphics、Foundation、AppKit），不引入第三方 Swift 包。GUI 的开发与测试见 [GUI README](../apps/gui/README.md)。

## 回归检查

```bash
swift test
```

```bash
./scripts/check-recover.sh
python3 scripts/check-cli.py
python3 scripts/check-authenticators.py
python3 scripts/check-sync.py
```

日常回归优先使用 fake 验证：`check-cli.py` 在独立临时库中自动切换批准、拒绝和锁屏，检查被拒绝的新建/覆盖不修改库、命令不执行、拒绝日志打码、解锁后独立请求可成功、索引修复和授权说明。它不依赖真实指纹操作，也不锁定电脑屏幕。验证器回归另用 RFC 6238/4226 向量、Python 标准库 HMAC、独立 CBOR 解码及已安装的 OpenSSL 验签；运行时不增加第三方 Swift 依赖。

## 真机冒烟

先 `swift build`，再在自己的 Terminal 中运行 `python3 scripts/accept-hardware.py --work <独立空目录>`。脚本不启用软件密钥，使用真实 Secure Enclave；仅用调试版的 `KAGI_HOME` 隔离本机状态，所有存储值均为假值。按提示亲自批准、取消、查看弹窗和保存恢复密钥；恢复密钥不会被脚本捕获或写入验收记录。某步失败会停止，并在指定目录写入 `status.json`；人工核对后可用同一目录加 `--resume` 从取消写入场景继续，旧记录会保留。

该脚本覆盖普通终端场景。从 agent 发起时的弹框、取消、超时和锁屏用 `python3 scripts/accept-agent.py --work <测试库目录> --name <环境名> [--lock]`，分别在 Terminal 和 agent 里运行；测试库由用户自己建，做法写在脚本开头。另一台物理 Mac 及 release 二进制操作需要分别验收；模拟通过不代表系统弹窗或真机验证通过。agent 场景的排查见[已知问题](已知问题.md)。

## 调试版环境变量

调试版（`swift build` 不加 `-c release`）可以设置这些环境变量：

- `KAGI_DEBUG_SOFTWARE_KEYS=1`：用软件密钥代替 Secure Enclave，不弹指纹框。
- `KAGI_DEBUG_AUTH_DECISION=approve|deny|locked`：仅在启用软件密钥时生效，默认 `approve`。`deny` 模拟取消本次验证；`locked` 同时禁止取值和读取索引。未知取值直接报错，不会默认批准。调试输出显示本次模拟授权说明。
- `KAGI_HOME=<目录>`：换掉本机状态目录。

再配合 `kagi _debug-init --vault <目录>` 建一个假库，就能在没有指纹的情况下跑命令。发布版里没有这些。测试和调试只用明显的假值。

## 平台

当前安全后端和执行器仍依赖 macOS，尚未实现 Windows/Linux/iOS/Android 支持。GUI 使用 Flutter 以同时覆盖桌面和手机，但跨端界面不等于跨端安全后端，需要分别适配、验收。
